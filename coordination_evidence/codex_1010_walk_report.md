## Narrow instrumentation proposal (read-only inspection; not implemented)

Consequently neither an HTTP rejection count nor a stalled position proves a void hit. `map_test.py` calls spatial_slide in the resident reconciliation immediately before publishing positions; this is the appropriate controlled-human observation site. The `/control/input` stale check runs before player_control.submit_input, so genuine stale-window rejection has not applied the input and is safe for this probe's bounded retry.

Propose an optional observer at slide, disabled by default, with source box identity preserved alongside the selected geometry only in observer mode. Emit contact when a specific box actually reduces an X/Y sweep endpoint, or holds an initially embedded actor. Emit ordinary bounds-clamp separately. For void boxes record actor ID, tick, window epoch, box ID, phase (x/y/embedded) and before/desired/resolved local positions; do not infer void contact from the difference between desired and resolved alone. Count distinct actor-tick void contacts once, with optional individual contacts in a bounded ring buffer. Observe the real reconciliation exactly once, without replaying movement or recomputing a second competing collision result. Return values, epsilon tolerances, box order, default optimized candidate filtering, and default golden behavior must remain identical. Include embedding in tests as distinct from attempted crossing; cover ordinary wall plus void interactions and both optimized/plain sweep paths.

A proposed opt-in diagnostic endpoint, e.g. `/window_probe`, could expose a tick/world/window-stamped copy containing controlled human void-hit totals, allocator owned rows and configured budget, main human UID-to-slot mapping, cache size/capacity, in_flight count/configured limit, and integrated coordinates. Reset counters on session new/continue/world replacement, then snapshot a start baseline so the probe uses per-run differences. This avoids changing frame/map export schema or consuming map deltas. Scope it to an explicitly enabled probe flag with flag-off behavior unchanged; no endpoint or flag was added here.

Existing enforceable capacity contracts are specific: `harness/window.py` WINDOW_ROW_BUDGET defaults to 800 and SlotAllocator.allocate checks headroom before mutating; assert sampled owned rows <= the actual allocator budget. `systems/worldgen/service.py` ChunkCache.put evicts beyond the configured capacity (default 512); assert cache size <= actual capacity. Expose the configured values instead of hardcoding those defaults. Resident slot stability can then be checked directly against `_human_uid_by_slot` through the sampled UID-to-slot mapping. These bounds establish those containers' occupancy, not an RSS-growth threshold or a universal bound on all semantic memory. No constant integrated-chunk maximum should be inferred from the row budget: chunks have different row counts and the rings cover every resident.

Record main-backend RSS (current probe), optionally worker-tree RSS under a separately named metric, and occupancy samples/start/end/peak. Even if all capacity checks pass, leave total-memory bounded-growth acceptance unknown until a concrete RSS or retained-container contract is specified. Resident memory graphs, per-chunk modified-state stores and Python allocator retention are outside the listed cache/row limits. The roadmap's phrase “memory growth bounded” provides no numeric RSS rule; inventing a percentage or MB allowance would overstate the evidence.
